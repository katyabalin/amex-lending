Product thinking
What I'd put in the backlog
Three real user pain points this concept addresses - grounded in user research and app feedback - with how I'd measure success.
User pain point #1 - cost opacity
Cardmembers don't understand how much compounding interest actually costs them. The current app shows your balance but not the total cost of carrying it. This tool surfaces total interest in real dollars proactively - before the user has to go looking for it. User story: "As a cardmember with a balance, I want to see what I'll actually pay in total so I can make an informed decision about Plan It®."
User pain point #2 - reactive surfacing
Plan It® is only surfaced after a purchase - not when a balance is already high and compounding. A proactive in-app nudge when balance crosses a threshold (e.g. $500+) would convert more users and reduce revolving interest exposure. This is a low-effort, high-impact backlog item with clear A/B test potential.
User pain point #3 - decision paralysis
The app presents all Plan It® durations equally with no guidance on which is best. Users have to do the math themselves. This tool auto-surfaces the best value duration based on APR - removing friction and improving feature adoption without requiring the user to understand fee rate math.
Proposed feature - lending nudge
An AI-powered in-app card that appears when balance exceeds a threshold, showing exactly how much Plan It® saves vs. carrying interest, with a one-tap enrollment flow. Personalized by APR, balance, and payment history. Estimated impact: 15-25% lift in Plan It® adoption among high-balance cardmembers.
Success metrics
Plan It® adoption rate among cardmembers with balances >$500 · Reduction in revolving balance month-over-month · NPS on lending features · Time-to-enroll from balance threshold trigger · Interest revenue impact vs. increased cardmember satisfaction and retention
